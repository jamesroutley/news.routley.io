Blanking Beavers: Results and Open Problems

SCENARIO: The year is 1950, and a brand new Turing machine, the first of its kind, has been installed at a research facility. Lots of people want to use it, but the machine has just one tape. A program’s execution can be affected in undesirable ways by data left over on the tape from a previous program run, and so as a matter of etiquette the convention is adopted among the machine’s users that the tape is to be wiped clean after each use. Rather than cleaning the tape manually after program execution, the programmers soon figure out how to automate the wiping process by writing their programs with cleanup routines at the end. Such programs are called self-cleaning.

Here’s a question: when started from the blank tape, what is the longest that a Turing machine program of a given length can run before reaching the blank tape again? We call this the Blanking Beaver problem, and the function that maps program length to maximum blank-to-blank runtime we call BLB.

We leave the tape blank out of consideration for others. As it was said in olden times: “Be kind, rewind.” But suppose we don’t care about the other users of the Turing machine. Instead, we just want to know the longest a program can run before halting, without any regard for the junk left over on the tape. This is the classic Busy Beaver problem (BB).

BB is a notorious example of a function that is uncomputably fast-growing. What about BLB? Here are the best known values:

At first glance it would appear that BLB grows faster than BB. Actually the story becomes a little more complicated when we consider different ways of measuring program length, but clearly BLB grows fast. And it is obvious from experience that BLB is equicomputable with BB, in the sense that an oracle for one problem could be used to solve the other.

We’ll examine those values later. But first there is a basic question about BLB. Is it possible to prove that BLB(s) < BLB(1 + s)? That is, given some BLB value, can we obtain a greater BLB value by adding one extra state? This is clearly true, but it is surprisingly difficult to prove.1 It is easy to prove the analogous statement for BB by construction, since a halting program’s “halt instruction” offers a convenient modular hook-in point for the new state to attach. But a self-cleaning program does not need to have a halt instruction, so there is no nice modular interface. On the other hand, it is easy to prove that BLB(s) < BLB(2 + s) via a standard instruction-padding construction.

About the 2x5 and 6x2 categories: I have attempted a search of the 2x5 space, and the best I could find was a program that blanks the tape in around 10100 steps. I don’t believe that is anywhere close to the true value of BLB(2,5), and I didn’t bother to record it. As far as I know, nobody has attempted a search for BLB(6,2). There is one known 6x2 tetrational blanker (~10↑↑16); however, it is just an extension of a former BB(6,2) champ found by Pavel Kropitz. Again, I do not believe it is anywhere close to the true value of BLB(6,2). I consider both of these to be fully open problems.

I claim the following:

  • The current 4x2 and 2x4 BLB champs are in fact the true champions.
  • The current 5x2 champ is likely not the true champion.
  • The current 3x3 champ looks like it could be the true champion, but then again it might not be.

I have not produced a formal proof of the 4x2 and 2x4 values in Lean / Rocq / etc, but I am claiming that such a proof could be produced2. Such a proof would be just like the BB(5,2) proof. All of the proof techniques developed for the halting problem – backward reasoning, CPS, FAR, etc – can be easily adapted for the blanking problem.

The machine is started with a blank tape in state A. The program is run until the tape becomes blank again. What happens after that? We are not requiring halting here, so the machine will keep going6. What does it do?

This depends on the state the machine is in at blank time. There are a few possibilities. If the machine is in state A, then it has returned to its initial configuration7, and it will proceed to do whatever it has just done again and again and again. Otherwise, the machine is in some other state. It could at that point do something totally different, effectively restarting computation as a different program with a different behavior. Or it could enter into some kind of obviously degenerate configuration, thereby signaling that the computation is terminated.

A priori it is not clear what a BLB champion should be expected to do after reaching the blank tape. The tiny BLB(2,2) champ reaches the blank tape in state A, while the BLB(2,3) champ enters into a simple four-step loop after reaching blank. In every other case the champ almost immediately enters into an obviously degenerate configuration. Recall the zero-reflexive instructions mentioned earlier. If a zero-reflexive occurs on the blank tape, then the machine will get stuck in that single instruction forever. We call this behavior spinning out, and that is what they all do.

In particular, no non-trivial known champs reach blank tape in state A. Indeed, in the searching that I’ve done, it seems that aiming to reach the blank tape in the initial state is a terrible strategy for achieving a high BLB score. Here are some Blanking Beaver open problems. They are grouped as theory, search, and proof.

Theory

  1. Prove (preferably by construction) that BLB(s) < BLB(1+s).
  2. Is it always the case that BB(s,c) < BLB(s,c)?
  3. Define upper bounds for BB and BLB in terms of each other.
  4. Characterize the post-blanking behavior of BLB champions, or show that this cannot be done.
  5. Given a BB champion program, what is the shortest extension of that program that blanks the tape?

Search

  1. Find a good value for BLB(2,5).
  2. Find a good value for BLB(6,2).
  3. Find a value for BLBi(9) better than BLB(3,3).

Proof

  1. Formally prove BLB(4,2).
  2. Formally prove BLB(2,4).
  3. Formally prove BLBi(8).
  4. Prove whether the BLB(5,2) Cryptid blanks the tape.
  5. Develop novel proof techniques that apply specifically to BLB.
