Submitting a patch to GNU sed

November 12, 2026

I’m working on a long option parser for Hare and decided to use sed as an example (because Hare stdlib’s getopt has a sed example). This is sed’s man page:

Zoom in..

Enhance..

Huh, what does -V do?? It’s not described in the man page. Let’s try it.

» sed -V
sed: option requires an argument -- 'V'

Okay.. giving it a wut argument resulted in no error message and just the usage text. So I found the GNU sed project page, cloned the source, and found it really wasn’t doing anything. In fact, -V used to be a version flag but it was removed in version 4.1 (released in 2004!).

So I made and submitted a patch for it! This is why I love open source software.

The change itself is pretty simple but has been part of GNU sed for over 22 years! I also learned something new about optstring (via man 3 getopt). A character followed by a single : is a required argument, but if it’s followed by a double ::, it is an optional argument.

Also! W; makes -W foo equivalent to --foo! That’s wild!

I think most modern-day programmers are familiar with submitting changes to source forges like GitHub or GitLab, but GNU is a pretty old project and it’s not obvious how to do that. You actually have to send the change in via email!

You could do that by generating a patch file via git format-patch and pasting the text into a standard email client, but the cool way is to send the email directly from git. That’s right, git has builtin support for emailing patches. Here is a beginner-friendly walk-through of how to set that up. I also learned you can configure git to use a credential helper to automatically get the password from secure storage (like a password manager), which is what I did too.

With all that done, I was ready to submit the patch:

» git send-email --to="bug-sed@gnu.org" HEAD^
