Introducing LFM3: Every Modality for Specialized Intelligence

Today, we’re excited to announce LFM3, our new generation of Liquid Foundation Models (LFMs) built for specialized intelligence. The LFM3 model family is multimodal by nature and brings text, vision, audio, omni, and decision models onto one new shared backbone. The first release of the LFM3 family covers models in the 2B parameter range.

Built on a new hybrid architecture and 22T tokens of pre-training, LFM3 is far more expressive than LFM2 while maintaining its efficiency. The extra capacity in a small, fast model makes LFM3 the ideal starting point in its class for specialized intelligence: this is because it can be fine-tuned locally, it can run on any device, and it is capable enough to become a reliable expert on a specialized task.

The base and post-trained models are open-weight and available today on Hugging Face, our Playground, and the Liquid AI API. Check out our docs on how to run and fine-tune them locally.

New architecture for more expressivity

LFM2 showed that a hybrid of short convolutions and attention could run fast on-device without sacrificing quality. Its design came from our automated hardware-in-the-loop architecture search. For LFM3, we used this search to redesign that architecture for agentic use cases, which need more capability per parameter and fast inference over long contexts.

We also expanded the hardware in the loop, from CPUs in one phone and one laptop for LFM2 to 14 device and backend combinations for LFM3: phones (Samsung Galaxy S26 Ultra and OnePlus 15), a Raspberry Pi 5, laptops (Apple M4 Max and AMD Ryzen AI), and Arm and x86 cloud CPUs, plus GPUs and the Qualcomm Hexagon NPU.

Gated short convolutions still make up over half the layers. To add capability without slowing down long contexts, we tried swapping some of them for other sequence blocks, and sliding-window attention (SWA) gave the best quality–speed tradeoff. We kept the other changes described below only where they improved quality without a meaningful speed cost. The payoff shows at long context. Per parameter, LFM3-1.7B matches LFM2-1.2B on short prompts across edge devices, and with 8K tokens in context it is about 25% faster.

Tri-hybrid layer mix. LFM3 combines three operators: gated short convolutions, sliding-window attention (SWA), and global attention. Of its 24 layers, 13 are convolutions, 5 are SWA with a 256-token window, and 6 are global attention. The convolutions also use a kernel size of 7, up from 3 in LFM2.

Head-wise gated attention. A sigmoid gate scales each head’s output, so a head can switch off when it has nothing to add. This can help suppress activation outliers that hurt quantization and improve training stability.

Partial RoPE. Global attention layers rotate only the highest-frequency half of each head and leave the low-frequency half unrotated, so those dimensions match on content regardless of distance. SWA layers keep full RoPE.

Sandwich norm. Each block normalizes both its input and its output, which helps keep activations well-scaled.

LFM3 uses the same 128K vocabulary as LFM2.5-8B-A1B, built to tokenize non-Latin scripts more efficiently.

Training. LFM3-1.7B-Base was pre-trained on 22T tokens. Compared with LFM2, the mix adds more scientific papers, repository-level code, a wider range of knowledge sources, and considerably more math. The final 3.5T tokens are a mid-training stage on curated, higher-quality data, with a larger share of agentic traces and diverse tool calls to prepare the model for agentic post-training. This stage also extends the context window to 256K tokens.

A multimodal family for every need

The first LFM3 release includes six models, all branched from the same LFM3-1.7B-Base backbone and all around 2B parameters. Four of them cover different input modalities (text, vision, audio, and omni), and the last two are decision models specialized from the vision and omni models. Instead of running one large general-purpose model, you can pick the one that fits your use case, customize it, and run it on-device.

For a deeper dive into the performance and inference results behind these models, refer to the respective model cards.

Text

LFM3-1.7B is a text model for local agents and specialized applications with a 256K-token context window.

It is post-trained to run in agentic harnesses such as Hermes Agent, Pi, and OpenClaw. It can triage your inbox, manage your calendar, research topics on the web, send you morning briefings on WhatsApp, and use tool search to find the right tool among thousands of options. Since tokens are free, dozens of agents can run continuously in the background. You can adapt it to your domains, harnesses, and tools with a short fine-tuning run on a single GPU.

On agentic tasks, LFM3-1.7B competes with models several times its size. It leads on instruction following and function calling on BFCL and ToolSandbox, and beats Qwen3.5-9B on long tasks in browsers and business apps (WebArena-Verified, AutomationBench). Larger models still win on agentic coding and knowledge, where size matters most, but search helps close the knowledge gap, nearly doubling its score on Humanity's Last Exam.

To achieve these results, the model went through four stages of post-training:

  • Supervised fine-tuning (SFT): 1.75T tokens across various tasks, including chat, reasoning, tool calling, and agentic traces.
  • Mixed reinforcement learning: many domains trained at once, from math and code to SQL and structured outputs. A length penalty in the reward keeps answers concise.
  • Multi-domain on-policy distillation (MOPD): six specialist RL teachers (code, math, tool use, long context, agentic work, and enterprise workflows) are distilled back into a single model.
  • Agentic RL: tasks from web browsing to office work are run inside real agent harnesses, preparing the model for deployment.

On-device, we measure metrics with llama.cpp at Q4_0 and a 32K-token context. LFM3-1.7B is the fastest model on all three devices, decoding 1.8 to 2.8 times faster than the next one, and it uses the least memory. Long contexts stay cheap: a full 128K-token context needs 1.6 GB of KV cache, against 4.3 GB for Qwen3.5-4B and 5.6 GB for MiniCPM5-2B.

On a single NVIDIA B300 with SGLang in BF16, LFM3-1.7B can produce 3.6 billion tokens per day at 1,024 concurrent requests, more than any other model in this comparison.

To show what this throughput makes possible, we ran more than 300,000 LFM3-1.7B agents in parallel to investigate the Enron email archive.

LFM3-1.7B can be served at low latency under random traffic, enabling real-time use cases like online fraud detection when run on Liquid RIPL. P95 request latency remains stable even under heavy load, outperforming competing models served on vLLM.

Vision

LFM3-VL-2B can watch, reason, and understand the physical world:

  • Video understanding: for the first time, an LFM vision model takes video as input. Ask questions about a recorded lecture, a walkthrough filmed on your phone, or a clip from a camera feed.
  • Thinking: the model reasons step by step before answering. This helps it better understand user inputs and solve harder visual questions such as math, charts, and multi-step problems.
  • Spatial and embodied reasoning: the model’s ability to localize objects and reason about their spatial relationships provides a strong foundation for downstream robotics applications.

LFM3-VL-2B is a leap in performance over the LFM2.5-VL series. Across 62 vision benchmarks, LFM3-VL-2B scores significantly ahead of all models of similar size by at least 7.4 points, and despite its size, it matches the performance of Gemma 4 12B, a model more than 6 times larger, surpasses Gemini 3.5 Flash Lite and is within 2 points of GPT-5.6 Luna. Vision encoder

In addition to improvements to the LFM3 backbone, LFM3-VL comes with our new in-house vision encoder which uses 3× less compute than the SigLIP2 encoder in previous LFM VL models.

The Liquid vision encoder combines convolution and attention to make it significantly more efficient than its ViT counterpart at the same quality. The performance-efficiency graph below illustrates this. Our 164M-parameter encoder matches Qwen3.5-2B’s vision encoder at 55.9% average accuracy across 13 vision-language model benchmarks, while requiring 2.2× fewer FLOPs. 

For video, the encoder jointly embeds each pair of sampled frames into one temporal slice of visual features, halving the temporal sequence length before further encoding. Together, these choices make the encoder a foundation for both richer image understanding and efficient video processing.

Audio

LFM3-Audio-2B is a compact, fully featured audio model that runs locally on laptops and edge devices. It takes text or audio as input and responds with text, speech, or both.

LFM3-Audio-2B uses a new architecture with an audio encoder and codec developed in-house. It outperforms LFM2.5-Audio in speech quality and now supports 18 languages. New capabilities include audio understanding, general-purpose audio reasoning, and tool calling.

  • Voice chat: ask questions aloud and receive streaming replies in text and speech. For text-only responses, the model can also reason before answering.
  • Multilingual speech: transcribe, synthesize, and translate speech across 18 languages.
  • Audio understanding and reasoning: ask the model to interpret recordings and answer questions about the speech, sounds, and events they contain.
  • Tool calling: turn spoken requests into tool calls to control apps and devices. The model can also respond in text or speech alongside those calls.

Our new LFM-based audio encoder is built from a mixture of sliding-window attention and short-convolution layers, keeping memory utilization bounded. The new encoder is fully causal, allowing the model to process live microphone input and perform prefill while you speak. This reduces the wait after you finish, with time to the first token as low as 50 ms.

LiquidCodec, our new audio tokenizer, powers multilingual speech generation in both LFM3-Audio and LFM3-Omni. Built on the LFM3 architecture, LiquidCodec turns generated tokens into speech at about 87× real time on a single CPU thread (Apple M4 Max), supporting streaming decoding. 

Quantization compresses each 80 ms of speech into 12 discrete tokens and, in contrast to previous LFM Audio models, allows multiple tokens to be predicted iteratively in parallel rather than requiring sequential prediction. As the backbone generates new tokens, the detokenizer progressively converts them into speech, all faster than real-time so that conversations are smooth and responsive.

Omni

LFM3-Omni-2B is our first omni model, bringing vision, audio, and language together in a single model that can see, listen, and talk back:

  • Spoken visual question answering: Ask questions about images or real-world scenes using speech, and receive answers in text, speech, or both.
  • Audio-visual video understanding: Process video frames alongside their corresponding audio, allowing the model to reason about both what is happening on screen and what is being said or heard.
  • Multimodal tool calling: Combine visual context with spoken instructions to generate structured tool calls, enabling assistants to interact with applications and interfaces using both what they see and what users say.

LFM3-Omni supports cross-modal interactions that require understanding visual and auditory information together. Users can ask spoken questions about images, or provide videos with synchronized audio and ask questions that depend on both what is seen and what is heard.

In addition to cross-modal understanding, LFM3-Omni retains the core capabilities of the standalone LFM3 models, including visual question answering, speech recognition, speech synthesis, and language instruction following.

LFM3-Omni-2B is designed for efficient deployment in resource-constrained environments. Its capabilities enable conversational assistants that can provide context-aware guidance, support hands-free interactions, and help users complete tasks through natural voice commands. By combining visual understanding, spoken dialogue, and tool calling, it can support applications ranging from personalized education and everyday assistance to navigation of digital interfaces and robotic systems.

At 2.2B parameters, it brings this kind of multimodal assistant on-device. Examples include a tutor that looks at your handwritten math and answers your spoken question, a tablet you can walk around with and ask about what it sees, and in-car assistants that combine what the camera sees with what the driver says.

Decision

This release also brings two new decision models: d1-2B, built on LFM3-VL-2B, reads text and pictures, and d1-Omni-2B, built on LFM3-Omni-2B, also listens. Instead of writing an answer, they decide in milliseconds. Give them a situation (a support ticket, an invoice, an app screen, a photo, a voice note) and a list of questions, and they answer all of them in a single forward pass, each with a calibrated probability.

Beyond the new LFM3 backbone, the big change since d1-3B is typed answers. On top of yes/no, choices, and scores, both models can now:

  • Point: draw a box around what you describe, or find every instance of something, with a count.
  • Read: pull text, numbers, and dates out of a document, with the exact span they came from, and say “not found” when a field isn’t there.
  • Estimate: give a number with its likely range.
  • Pick: select every option that applies, each with its own probability.

Ask as many questions as you like: they’re read in one pass over the same input.

Made for specialized intelligence

LFM3 is built to be specialized. The 2B-class models are small enough to fine-tune on your own data and run where your application lives. The following two examples show this with LFM3-VL-2B. The first is a short fine-tune that turns it into an inspection model for one narrow industrial task. The second is a research extension that turns it into a robot controller.

Domain expertise: Specializing LFM3 for your field

While frontier models are powerful generalists, they are not necessarily experts in your particular use case. In this demo, we fine-tuned LFM3-VL-2B to find and classify defects in drone photos of wind turbine blades. Training used about 3,000 public photos (WTBs2025) with SFT and GRPO for a few hours on one A100. We then compared it with the base model and GPT-6 Luna on about 1,400 held-out photos.

Out of the box, LFM3-VL-2B and GPT-6 Luna correctly identify these defect types in fewer than 10% of images. A short fine-tune raises LFM3-VL-2B’s classification accuracy to 67% and improves detection F1 from 0.003 to 0.11, compared with 0.01 for GPT-6 Luna. Lightning-strike images illustrate the difference, where GPT-6 Luna often locates the defect correctly but labels it incorrectly, while the fine-tuned model correctly identifies a lightning strike. Beyond classification and detection, the model can answer natural-language questions about the same image. For example, it can locate visible damage or write a brief inspection finding including the defect type, supporting evidence, and location.

Robotics: teaching LFM3 to act

We investigate how LFM3-VL-2B can serve as a basis for robotics applications. We consider three complementary directions: (1) high-level tool orchestration, (2) vision-language navigation, and (3) low-level manipulation.

Orchestration. Building on LLM-based robot planning and control (SayCan, Code as Policies) and recent physical orchestrators (VoLo, Gemini Robotics ER 2), we fine-tuned LFM3-VL-2B to operate a robot arm through tools. Given a request and the current camera image, it reasons step by step, grounds objects by pointing, measures them with depth tools, and manipulates them via motion planners. It then checks each outcome in the next image and reports back, including when a request is out of reach or ambiguous. The tasks feature relational selection, sorting by measured properties, and environment perturbations, all simulated in Isaac Sim. No architectural change was needed. A rank-32 LoRA adapter was trained on about 40,000 samples, combining manipulation trajectories with general tool-use and pointing data, and took about six GPU-hours on a single AMD Instinct MI325X. Paired with a fine-tuned d1-2B skill monitor, we can further double recovery success under disturbances such as slips, jams and drags.

Navigation. For vision-and-language navigation, LFM3-VL-2B reads a route description and a short history of RGB frames to predict navigation targets and residual-quantized trajectory primitives, inspired by the action interface of LightNav-0. Each decision consists of five tokens: two spatial/control tokens and three hierarchically quantized codes encoding a ten-waypoint path that a velocity controller can track. We only repurpose 2,068 vocabulary tokens; the architecture is otherwise unchanged. We train on 2.8 million samples for 72 GPU-hours on MI325X GPUs. In unseen validation scenes, the resulting model achieves success rates of 53% on R2R and 43% on RxR under a strict continuous-control evaluation protocol with wall sliding disabled and explicit stopping required. We further observe robustness across varying camera angles and instruction languages. On a Jetson AGX Orin, our navigation model updates waypoint trajectories at over 2.5 Hz using TensorRT FP16 without visual prompt caching.

Manipulation. To turn LFM3-VL-2B into a vision-language-action (VLA) model, we adopt parallel action prediction inspired by OpenVLA-OFT and StarVLA-α: a small residual MLP maps the hidden states of eight action-query tokens to an eight-step chunk of continuous robot actions in a single forward pass. Proprioception is provided both as discretized text and through an embodiment-specific learned projection, and the whole network is fine-tuned end to end. We trained a single generalist checkpoint for 170 GPU-hours on MI325X GPUs, on simulated and real-robot data from 15 embodiments, ranging from single arms and mobile manipulators to bimanual platforms and a humanoid. The resulting VLA achieves 96.2% average success across the four LIBERO suites and 45.7% on RoboCasa-GR1 tabletop tasks. On a Jetson AGX Orin, it can generate action chunks in under 50 ms using TensorRT at FP16 precision.
